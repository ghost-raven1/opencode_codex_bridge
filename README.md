# CodexBridge

Локальная сборка **0.2.0** для **OpenCode CLI 1.3.2**: основной агент подключается к моделям через вход Codex, а инструмент `codex` делегирует задачи официальному Codex App Server по stdio. Отдельный плагин `@codexbridge/companions` отображает пиксельных персонажей на macOS и озвучивает ответы. OpenCode остаётся основным терминальным интерфейсом.

## Запуск

Нужны Node **24.15+ в ветке 24**, установленный OpenCode **1.3.2** и вход в Codex. Для компаньона нужны macOS и Xcode Command Line Tools.

```sh
nvm use
npm ci
npm run check
npm run test:native
node scripts/smoke-companion-activity.mjs # реальный OpenCode: длительный инструмент и запоздалый idle
npm run connect:codex
npm run setup:snip
npm run setup:playwright
npm run companion:build
npm run bundle:all
npm start -- companions /absolute/path/to/project
```

В CLI: `/codex Исправь ошибку и проверь тесты`. Плагин вернёт `threadId`; передай его следующему вызову инструмента `codex`, чтобы продолжить ту же сессию. Модель берётся из настроек Codex; поле `model` позволяет явно выбрать другую. Мост использует свою зафиксированную зависимость `@openai/codex@0.159.3`, а не случайную глобальную версию.

`npm run connect:codex` подключает существующий вход ChatGPT в Codex и сохраняет каталог моделей. Для нового входа выполни `npm run connect:codex -- --login`: мост откроет официальный браузерный вход через Codex App Server. В уже настроенном OpenCode эти способы доступны через `/connect` → **Codex via bridge**. Учётные данные обрабатывает официальный Codex.

Обычные сообщения OpenCode также используют этот вход: в `/models` выбирай **Codex via bridge**. Сборка сохраняет модель из настроек Codex, если она есть в каталоге, иначе использует модель по умолчанию из каталога. Для коротких служебных запросов используется `gpt-5.6-luna`, когда она присутствует в каталоге. Смена модели сохраняет инструменты и диалоги разрешений OpenCode. После смены аккаунта обнови каталог командами `npm run connect:codex` и `npm run bundle:all`, затем перезапусти CLI.

Мост получает access token через локальный RPC `getAuthStatus` и поручает обновление самому Codex. В хранилище OpenCode записывается только несекретная отметка `codexbridge-managed`; токен используется в памяти для запросов Responses. Основной агент OpenCode отправляет эти запросы через адаптер моста, а инструмент `/codex` делегирует целый ход App Server по stdio. Каталог `model/list` может быть кешированным: доступ к выбранной модели подтверждается завершённым запросом, а не одним наличием в списке. [Протокол Codex App Server](https://learn.chatgpt.com/docs/app-server).

## Профили

| Профиль | Запуск | Поведение |
| --- | --- | --- |
| quiet | `npm start -- quiet /project` | Codex, планирование, MCP документации, LSP, snip; без голоса и персонажей |
| jarvis | `npm start -- jarvis /project` | Совместимое имя голосового профиля; локальная озвучка и диктовка macOS |
| companions | `npm start -- companions /project` | Персонажи, локальный либо системный синтез речи и диктовка macOS |

Конфигурации создаются в `.local/profiles/`; глобальный файл OpenCode не переписывается. OpenCode может объединять их с личными настройками. Повторный `bundle` пересоздаёт только сгенерированный профиль, поэтому постоянные изменения вноси в генератор либо в проектные настройки.

Озвучка поддерживает встроенный **AVSpeechSynthesizer macOS** и бесплатный локальный **Qwen3-TTS через MLX** на Apple Silicon. Установка локального движка: `npm run setup:tts`, затем `npm run bundle:all`. Для закреплённого MLX нужны macOS 26+ и Python 3.12; установщик использует отдельное окружение в `.local/tts/`, скачивает закреплённые CustomVoice и Base (примерно по 2,2 ГБ) и не меняет глобальный Python. В памяти находится одна модель; она меняется при переходе между базовыми и новыми голосами. После установки синтез работает без сети и API-ключей. Выбранные модели — Apache-2.0, MLX Audio — MIT. [Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS), [MLX Audio](https://github.com/Blaizzy/mlx-audio).

В меню **✦** можно проверить голоса команды, остановить речь и выключить озвучку. Предпочтительные голоса ролей: LEAD — **Serena**, CODE — **Vivian**, RESEARCH — **Sohee**, REVIEW — **Ono_Anna**. DESIGN, OPS и TEST используют три новых синтетических тембра `designer-local`, `devops-local`, `tester-local`; исходные образцы созданы VoiceDesign, при работе используются локальные Base и reference WAV. Каждый из четырёх видимых персонажей получает свободный голос. Тембр фиксируется на всю публичную реплику и не меняется между её фрагментами.

Один worker и общая очередь исключают одновременную речь. Qwen передаёт звук порциями примерно по две секунды; плеер начинает после четырёх секунд готового звука либо завершения короткого фрагмента. Стартовый бюджет — **20 секунд**, без зависимости от предыдущей реплики. После сбоя macOS закрепляется за всем вызовом агента. Уже начавший звучать фрагмент не повторяется; следующие читает резервный голос. При одном установленном русском голосе роли в резервном режиме звучат одинаково; совпадение тембра с Qwen не гарантируется. Отсутствие старта системной речи допускает одну пересборку синтезатора. Stop и выключение голоса не запускают повтор.

`/voice-test` проверяет голос; `/companions` явно включает демонстрацию команды. Эти slash-команды используют обычную настроенную модель OpenCode для вызова инструмента `companion`; меню ✦ работает без запроса к модели.

Для ввода нажми **кнопку микрофона в строке меню** или **✦ → Начать диктовку**. Надиктуй текст, сделай паузу около секунды и скажи **«Отправить»**. Сначала сохраняется черновик, затем передаются события вставки и отправки в OpenCode. Повторное нажатие кнопки завершает обычную диктовку и вставляет текст без отправки модели. Если доставка текста завершилась ошибкой, голосовая отправка блокируется до восстановления черновика, новой успешной диктовки или явной очистки. HTTP-ответ подтверждает публикацию события, но не действие терминала: проверь начало задачи в CLI.

**Старт голосом:** введи `/voice-wake-on` или включи **✦ → Активация по слову «OpenCode»**. Значок ✦ находится в верхней строке меню macOS справа; `/voice` открывает это меню из CLI. Скажи **«OpenCode»**, надиктуй запрос, сделай паузу и скажи **«Отправить»**. Поддерживаются также «опенкод» и «опен код». Слово пробуждения убирается из черновика; слова после него сохраняются в той же записи. Фоновая беседа не становится запросом. Во время речи персонажей слушатель приостанавливается и возвращается через 0.8 секунды после её окончания. Синий значок уха показывает активное прослушивание. `/voice-wake-off` выключает только слово пробуждения; кнопка микрофона остаётся доступной. По умолчанию фоновое распознавание выключено; явное включение сохраняется. `/voice-wake-on` также разрешает диктовку, если она была отключена.

Отдельные голосовые команды: **«Очистить ввод»**, **«Отменить диктовку»**, **«Остановить речь»**, **«Остановить задачу»**, **«Скрыть компаньонов»**, **«Показать компаньонов»**, **«Новая задача»**, **«Выключить голос»**, **«Включить голос»**, **«Выключить диктовку»**, **«Помощь по голосу»**. Полная справка есть в меню ✦. Командные слова внутри обычного предложения остаются текстом; системные разрешения голосом не обходятся.

macOS запросит доступ к микрофону и распознаванию речи. **Отменить** отбрасывает текущий ввод. Диктовка ограничена 60 секундами и запускается кнопкой или включённым словом пробуждения. Фоновый слушатель обновляет ограниченные сессии распознавания без перезапуска аудиоустройства; при ошибке останавливается с видимым состоянием и допускает явное повторное включение. Во время записи синтезатор останавливается, чтобы не распознавать свой ответ. Системное распознавание может обращаться к сервисам Apple в зависимости от языка и доступности локальной модели.

**Танцы под музыку:** введи `/music-on` или включи **✦ → Реагировать на музыку**. `/music-off` отключает музыкальный захват. `/music-on` также разрешает микрофон, если диктовка была отключена. Этот отдельный режим выключен по умолчанию; после включения микрофон остаётся активным до его отключения, а выбор сохраняется. SoundAnalysis локально отличает музыку от речи, затем детектор устойчивого ритма синхронизирует семь разных танцев. В меню появляется оранжевая индикация и оценка BPM. Аудио не сохраняется и не отправляется модели. Диктовка временно забирает микрофон; после неё музыкальный режим возобновляется, если всё ещё включён. **Выключить диктовку** отключает диктовку, слово пробуждения и музыкальный захват, сбрасывая оба фоновых переключателя. При повторном разрешении диктовки фоновые режимы сами не включаются. Слово пробуждения и музыка могут работать одновременно; запрос временно приостанавливает музыкальный захват. Музыка не создаёт новых персонажей и не продлевает завершённую задачу; системное уменьшение движения отключает танцевальные движения.

В **✦ → Черновики диктовки** доступны просмотр, повторная вставка, копирование и очистка истории текущего проекта. Хранятся последние **20** текстов по пути `~/Library/Application Support/CodexBridge/dictation/<sha256>/drafts.json`; ключ вычисляется из канонического пути проекта, запись атомарная, права файла — `0600`. После перезапуска история доступна в меню, но не вставляется автоматически. Повторная вставка не удаляет копию и не отправляет запрос модели; отправка требует отдельной команды пользователя.

**✦ → Выключить диктовку** либо `/dictation-off` отменяет запись и запрещает её повторный запуск. Настройка сохраняется после перезапуска; голос продолжает работать. **Включить диктовку** или `/dictation-on` только разрешает ручной запуск, микрофон автоматически не включается. После пересборки локальная ad-hoc подпись меняется, и macOS может снова запросить разрешения. Разрешения выдаются самому приложению; настройки защиты macOS сборка не изменяет. Приложение запускается через LaunchServices, чтобы macOS запрашивала разрешения у CodexBridge Companions, а не у родительского терминала.

Jarvis сохранён в составе и MCP-конфигурации, но отключён во всех готовых профилях: ввод и воспроизведение обслуживает приложение macOS. Smart Voice Notify обслуживает только уведомления; его TTS и звуки отключены. Ключи ElevenLabs/OpenAI для голоса не нужны. Озвучка продолжает работать, даже если файлы персонажей недоступны.

## Системный доступ

Codex стартует с `workspace-write`, `approvalPolicy: on-request`, `approvalsReviewer: user`. До делегирования OpenCode запрашивает разрешение `codex`. Выход за разрешённые границы передаётся в отдельный запрос `codex_system` с командой, директорией и причиной. Ответ применяется к конкретной операции; запрос расширения прав ограничен одним ходом. Модель не получает инструмент самостоятельной выдачи разрешений.

Отмена OpenCode прерывает ход и завершает дочерний процесс. Ошибка содержит известные `threadId`/`turnId`. После обрыва проверь изменения перед повторным запуском: отмена не откатывает уже выполненные действия. Продолжить сессию другого проекта нельзя; параллельное продолжение одного `threadId` отклоняется.

Произвольные интерактивные вопросы Codex пока не пересылаются как текстовые формы OpenCode; неподдерживаемые RPC получают явную ошибку. Мост не включает `danger-full-access` и не запускает `sudo` сам по себе.

## Отдельный плагин персонажей

Пакет находится в `packages/companions/` и не зависит от пакета моста. Его можно подключить в другой OpenCode-проект. `companion:build` создаёт локальный `.app` с постоянным bundle ID и ad-hoc подписью для системных разрешений; глобальная установка не требуется. Настройки читаются из `.opencode/companions.json` проекта, затем из выбранного профиля.

```json
{
  "enabled": true,
  "speech": "all",
  "tts": {
    "engine": "local",
    "voices": { "coordinator": "Serena", "developer": "Vivian", "researcher": "Sohee", "reviewer": "Ono_Anna" }
  },
  "modelOpenings": true,
  "language": "ru-RU",
  "dictation": true,
  "showOnStart": false,
  "appearance": { "mode": "presets", "roles": {} },
  "maxVisible": 4,
  "scale": 1,
  "agentRoles": {}
}
```

Обычный запуск создаёт меню ✦ без персонажей и без работающего таймера отрисовки, даже если в старой конфигурации осталось `showOnStart: true`. Персонажи появляются для реальных сессий. Демонстрация запускается явно через `/companions` или меню; она сохраняет действующие сессии, а `/companions-show` возвращает их на экран.

Каждый новый вызов агента получает короткое вымышленное имя: оно генерируется локально и не повторяется среди действующих персонажей. Имя видно рядом с ролью и доступно модели для вступления. Смена роли, сжатие истории, скрытие и переподключение сохраняют имя; новая задача получает новое. Генератор использует 400 комбинаций без отдельного запроса к модели; бесконечная уникальность между перезапусками не обещается.

Роль определяется по первому действию в русском или английском задании: планирование → LEAD, реализация → CODE, исследование → RESEARCH, проверка → REVIEW. Субагент получает роль по описанию и тексту своей подзадачи уже во время выполнения. Это локальная эвристика; если намерение не распознано, используется имя агента. Явный `agentRoles`, например `{ "explore": "researcher" }`, имеет приоритет. Ответ ассистента не меняет назначенную роль. Служебное резюме сжатия контекста не озвучивается; синтетическое продолжение сохраняет роль исходной задачи.

Стартовое вступление сочиняет текущая модель под задачу и роль через `companion_intro`: LEAD — план и команда, CODE — код и баги, RESEARCH — поиск, REVIEW — проверки, DESIGN — интерфейсы, OPS — инфраструктура, TEST — тестовые сценарии. Уместные мемы допускаются без обязательной шутки в каждой фразе. Фиксированного списка нет. Общая история `~/Library/Application Support/CodexBridge/openings.json` хранит хеши всех принятых вступлений и последние 14 текстов, атомарно с правами `0600`. Повтор после нормализации регистра и пунктуации отклоняется, включая после перезапуска; модель может предложить другую формулировку. Семантическую уникальность перефразировок этот фильтр не доказывает. Если модель пропускает инструмент, вступления нет. Отключение: `modelOpenings: false`; собственная непустая `workingPhrase` сохраняет ручной режим. Старая стандартная «Задача в работе» мигрирует в пустую строку.

Пресеты: LEAD с планшетом, CODE в фиолетовом, RESEARCH с книгой, REVIEW в чёрно-оранжевом. Состояния: ожидание, размышление, работа, успех, ошибка, запрос разрешения. По умолчанию `speech: "all"` включает голоса субагентов; при `coordinator-only` говорит только основная сессия независимо от её текущей роли. Озвучиваются завершённые текстовые фрагменты, включая промежуточные сообщения перед вызовом инструментов; reasoning и содержимое инструментов не читаются. Кодовые блоки и URL убираются из произносимого текста. Новое пользовательское сообщение останавливает речь соответствующего персонажа и удаляет его устаревшие реплики из очереди.

Делегированный Codex получает отдельного персонажа. Мост передаёт его публичные завершённые сообщения в структурированном поле `metadata.codexSpeech`; плагин не извлекает речь из произвольного вывода инструментов. Внутренние рассуждения и вывод команд в этот канал не попадают.

После завершения задачи персонаж остаётся до окончания генерации, очереди и воспроизведения его речи, затем ещё на **30 секунд**. Уход занимает **900 мс**. Пока задача или её озвучка продолжаются, таймер ухода не запускается. Запоздалый `idle` не завершает незаконченный ответ, ожидающий инструмент или промежуточный шаг `tool-calls`/`unknown`. Одновременно видны не более четырёх персонажей; вытеснение из группы не отменяет задачу или её речь.

Qwen выдаёт звук порциями примерно по две секунды в пределах одной генерации с неизменным голосом. Воспроизведение начинается после накопления четырёх секунд или завершения короткой фразы. Через 20 секунд ожидания проигрывается уже готовая порция; если звука ещё нет, включается macOS. Каждая новая задача получает полный стартовый бюджет. В памяти и очереди удерживается не больше 12 секунд невоспроизведённого звука; следующий текстовый фрагмент готовится во время текущего.

При опустошении буфера меню показывает **«Буферизация»**, персонаж остаётся на экране. Пауза без новых данных дольше 10 секунд считается сбоем. Резервный голос закрепляется до конца вызова агента, включая следующие публичные сообщения и сжатие истории. Новая задача или явное восстановление разрешает Qwen снова. Если текущий фрагмент уже начал звучать, при сбое он не перечитывается: полный текст остаётся в облачке, следующие фрагменты читает macOS. До первого звука резерв читает фрагмент целиком. Суммарная длительность генерации ограничивается по длине текста и числам.

В меню ✦ строка **«Озвучка»** показывает подтверждённое состояние: нет готовой реплики, синтез, очередь, локальное или системное воспроизведение, выключенный голос, пауза на диктовку либо ошибка. Счётчик показывает фрагменты, которые ещё не начали звучать. После сбоя и опустошения очереди доступно **«Восстановить голос для следующих реплик»**: старый worker завершается, движки сбрасываются, следующий локальный синтез получает полный бюджет холодного старта 20 секунд. Старый текст не повторяется. Во время исправного воспроизведения, непустой очереди, mute и диктовки восстановление недоступно; настройки микрофона и разрешения сохраняются.

Порции PCM соединяет AVAudioEngine с одним AVAudioPlayerNode без перезапуска устройства между ними. Рот реагирует на амплитуду воспроизводимого PCM и закрывается при буферизации. Резервный AVSpeechSynthesizer использует события слов. Нарисованные формы рта не означают распознавание фонем. Облачко находится над говорящим персонажем: до звука текст приглушён, слова плавно проявляются и подсвечиваются по мере воспроизведения. Для Qwen ритм слов оценивается по проигранному PCM; точных времён слов модель не передаёт. При тишине и буферизации проявление приостанавливается. Очередная реплика не заменяет уже звучащую, в том числе между её фрагментами. При выключенном звуке, переполнении очереди или сбое полный текст доступен сразу. Длинный текст можно прокрутить, выделить и скопировать; ручная прокрутка отключает слежение за текущим словом до следующего сообщения. Закрытие компаньона останавливает worker и освобождает память модели. Для подключения заново явно вызови `/companions-show` (действие `show` инструмента `companion`); обычные события задач не перезапускают закрытое приложение.

Анимация послойная: тело дышит, голова плавно поворачивается и реагирует на состояние задачи, мимика движется вместе с ней. Каждые 8–15 секунд запускается самостоятельный жест. Появление занимает **1650 мс**: частицы собираются у ног, фигура проявляется снизу вверх, мягко выравнивается и приветствует пользователя. Смена роли или внешности — поворот и вспышка цвета за **1400 мс**, без наложения двух голов. При уходе персонаж кланяется и растворяется в пиксельном потоке. Возобновление работы отменяет уход и плавно восстанавливает видимость. Отдельный лицевой слой содержит 8 форм рта, 6 фаз моргания и 4 эмоции на роль. Старые однослойные клипы удалены; новые позы тоже состоят из отдельных головы, тела, рук и предметов.

LEAD, CODE, RESEARCH и REVIEW перерисованы в пропорциях TESTER v2. Разные лица, волосы, одежда и предметы сохранены. Все семь ригов используют равномерный масштаб; мимика согласована с новыми лицами. Исходники и точные запросы ImageGen сохранены вместе со скриптами подготовки.

У каждой героини три базовые позы и **16 новых послойных рабочих/танцевальных рисунков**. Есть оба профиля, виды со спины и в три четверти, ходьба, колено, наклон к столу и работа сидя. Рабочие ракурсы выбираются по действиям инструмента и меняются через **8–14 секунд**; повороты проходят через нарисованные промежуточные виды без исчезновения. У каждой героини четыре настоящие танцевальные позы и отдельная последовательность раз в два музыкальных удара. Речь возвращает исходную позу с мимикой. Имя, голос и внешность сохраняются; слои загружаются при первом использовании. Подробнее — [docs/choreography.md](docs/choreography.md).

Семь пресетов используют отдельные руки и предметы. Пока агент думает или работает, непрерывный цикл показывает работу с его предметом; между акцентными жестами персонаж не замирает. **28 рабочих и 28 спокойных клипов**, по четыре каждого вида на роль, добавляют просмотр расписания, проверку компиляции, сравнение источников, подтверждение ревью, проверку композиции, телеметрии и тестов. На отдыхе персонажи переводят взгляд, поправляют предметы, расслабляют кисти и кивают. Жесты длятся 4–5 секунд и плавно смешиваются с основным циклом. Кешированный свет сверху слева, лёгкое затемнение поверхностей, тени от слоёв на одежде и мягкая тень под ногами сохраняют чёткую графику и прозрачность. В смешанной внешности выбранная голова совмещается с шеей выбранного наряда.

Реальные инструменты выбирают дополнительные жесты **чтения, поиска, редактирования, тестов, сборки, выполнения и делегирования** — семь действий для каждого из семи ригов. Под именем появляется текущий вид работы. Короткие действия удерживают жест на один такт, длительные продолжают его; смена плавно смешивается за 400 мс. Если один из параллельных инструментов завершился, оставшийся продолжает задавать анимацию. CODE печатает двумя руками поочерёдно; предметы в сидячей позе следуют за удерживающей рукой.

Команда приветствует нового участника. Родитель передаёт задачу субагенту, тот возвращает результат, при ошибке коллега реагирует поддержкой. Персонажи смотрят друг на друга, двигают руками и подтверждают получение; между ними летит маленькая карточка задачи или результата. Адресные действия используют реальные связи сессий OpenCode/Codex. Действия одного участника идут последовательно; повторная metadata не повторяет жест, новая задача и удаление отменяют старые действия. Восстановление группы не переигрывает старую передачу. Речь сохраняет мимику рта; системное уменьшение движения отключает командные эффекты.

Объём создают округлая светотень, небольшая перспектива при повороте головы и корпуса, отдельная глубина рук/предметов и мягкие тени, следующие за движущимися слоями. Освещение применяется после сборки мимики: рот и веки получают тот же свет, что и лицо. Суставы остаются на своих опорах, стопы — на земле. Это глубина послойного рисунка, полноценные 3D-модели не используются. Тени и три варианта освещения кешируются; смена позы или головы сохраняет исходную внешность.

Кеш сглаживает только прозрачный край примерно на один экранный пиксель. Системное уменьшение движения отключает декоративное движение и сокращает переход до **150 мс**. Скрытая или пустая группа не запускает таймер отрисовки. Контракт, команды подготовки и исходники — в [docs/assets.md](docs/assets.md); результаты фактических проверок — в [docs/validation.md](docs/validation.md).

**Перемещение:** зажми персонажа или подпись и перетащи всю группу. Положение сохраняется после перезапуска. **Скрытие:** правый клик по группе → «Скрыть компаньонов» либо одноимённый пункт меню ✦. Показать обратно можно из меню ✦ или командой `/companions-show`; `/companions-hide` скрывает группу. Скрытие сохраняется и не сбрасывается новыми событиями задач; голос продолжает работать. Пункт «Вернуть позицию на экран» восстанавливает доступное положение после смены мониторов.

**Размер:** потяни уголок внизу справа — размер окна меняется плавно от 50 до 200%. В меню ✦ также есть **«Размер компаньонов»** с шагом 25%. Группа, подписи и облачко масштабируются пропорционально; при нехватке места группа вписывается в доступный экран. Выбор сохраняется после перезапуска, сброс возвращает `scale` из конфигурации.

Диагностические JSONL-логи находятся в `~/Library/Application Support/CodexBridge/diagnostics/<hash-проекта>/companions.jsonl`; точный путь выводится в журнале OpenCode при подключении. Максимум три файла по 1 МиБ, права `0600`. Записываются переходы состояний, обезличенные ID, длительности синтеза/ожидания, переходы на резервный голос и ошибки с фиксированной причиной. Тексты задач и диктовки, речь, reasoning, токены и аудиозаписи в диагностический журнал не попадают. Отказ записи не останавливает задачу или голос.

Смешанная внешность собирается из двух основных слоёв: голова с волосами и одежда с предметами в руках. Режим `presets` использует семь готовых персонажей с отдельными подвижными руками и предметами; `seeded` детерминированно смешивает базовые слои по ID сессии. Можно переопределить роль:

```json
{
  "appearance": {
    "mode": "seeded",
    "roles": { "developer": { "head": "researcher", "outfit": "reviewer" } }
  }
}
```

Значения `head` и `outfit`: `coordinator`, `developer`, `researcher`, `reviewer`. Очки, наушники и книги входят в соответствующие нарисованные слои; независимого переключателя каждого аксессуара нет. Цвет и подпись роли сохраняются при смене внешности. Исходник — `assets/reference/team.png`, контракт графики — `docs/assets.md`.

## MCP для harness и других клиентов

```json
{
  "command": "node",
  "args": ["/absolute/path/to/CodexBridge/packages/bridge/dist/mcp.js"],
  "env": { "CODEXBRIDGE_PROJECT": "/absolute/path/to/target-project" }
}
```

Это транспортный пример: внешняя схема конфигурации зависит от клиента. MCP-вход содержит инструмент `codex`. Системный доступ подтверждается через MCP form elicitation; если клиент не поддерживает её, запрос отклоняется. Для OpenCode используй нативный плагин, чтобы разрешения отображались прямо в терминале. При длинных задачах увеличь timeout инструментов клиента. Существующий репозиторий harness здесь не изменяется.

## Проверки

```sh
npm run doctor -- --mcp
npm run check
npm run smoke:mcp
# Все MCP должны ответить; недоступный дополнительный сервер считается ошибкой:
npm run smoke:mcp -- --strict
# Только локальные MCP и тестовый сайт на localhost:
npm run smoke:mcp -- --offline
npm run smoke:lsp
npm run smoke:opencode
npm run smoke:codex
# Отдельно: использует лимит настроенной модели Codex
npm run smoke:inference
npm run smoke:provider
# Нативный жизненный цикл без речи и записи микрофона:
node scripts/smoke-companions.mjs
# Дополнительно: PNG на светлом и тёмном фоне; scale также 0.5 или 2:
node scripts/smoke-companions.mjs --visual --scale=1
# Пропорциональное масштабирование и сохранение выбора после перезапуска:
node scripts/smoke-companion-scale.mjs
# Реальное задание OpenCode с субагентом, локальной и резервной озвучкой:
node scripts/smoke-opencode-speech.mjs
node scripts/smoke-opencode-speech.mjs --inject-failure
node scripts/smoke-opencode-speech.mjs --reviewer
node scripts/smoke-reviewer-caption.mjs
# Проверка трёх новых тембров и переключения модели обратно на CustomVoice:
node scripts/smoke-specialist-voices.mjs
# Отдельные проверки со звуком; для второй нужны разрешения macOS и динамики:
npm run smoke:voice
npm run smoke:dictation
# Статус без микрофона; запись включается явным флагом:
npm run smoke:voice-wake
npm run smoke:voice-wake -- --acoustic
# Запросить разрешения macOS при первом запуске проверки:
npm run smoke:voice-wake -- --acoustic --request-permissions
# Замер пауз локальной очереди и образцы четырёх голосов:
node scripts/benchmark-speech.mjs --mode=both
node scripts/generate-voice-previews.mjs
```

`doctor` проверяет локальные зависимости, браузер и определения MCP во всех профилях. `smoke:mcp` отдельно проверяет handshake и список инструментов; для Context7 получает документацию, для Grep — пример кода, для OpenAI Docs — результат поиска, а в Chromium открывает локальную страницу, нажимает кнопку и сохраняет скриншот. Обычный режим сообщает о недоступном дополнительном сервере предупреждением, `--strict` завершает проверку с ошибкой. Отчёт: `.local/mcp/smoke.json`. Jarvis проверяется без запуска микрофона; MCP-вход Codex — без запроса модели.

Результаты и границы проверки — в `docs/validation.md`. `smoke:opencode` запускает временный локальный сервер и отключает голос; `smoke:provider` дополнительно проверяет настоящий ответ модели OpenCode через мост и чтение тестового файла. Последний использует текущий вход и лимит Codex. Нативный smoke использует отдельную копию приложения и проверяет запуск, показ, скрытие, демонстрацию и удаление персонажей; он не доказывает работу микрофона или качество озвучки. Последняя акустическая проверка контрольной фразы не прошла; повторная проверка микрофона отложена пользователем. GitHub Actions подготовлен, но CI считается проверенным только после реального запуска на GitHub.
