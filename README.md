# CodexBridge

Локальная сборка **0.2.0** для **OpenCode CLI 1.3.2**: основной агент подключается к моделям через вход Codex, а инструмент `codex` делегирует задачи официальному Codex App Server по stdio. OpenCode остаётся основным терминальным интерфейсом.

## Запуск

Нужны Node **24.15+ в ветке 24**, установленный OpenCode **1.3.2** и вход в Codex.

```sh
nvm use
npm ci
npm run check
npm run connect:codex
npm run setup:opencode
opencode /absolute/path/to/project
```

`setup:opencode` собирает мост, создаёт профиль `quiet` и устанавливает глобальную точку входа `~/.config/opencode/plugins/codex-bridge.js`. После этого обычная команда `opencode` загружает мост в любом проекте; при уже открытом CLI нужен перезапуск. Провайдер Codex и `/codex` добавляются в `~/.config/opencode/opencode.json`. При заданном `XDG_CONFIG_HOME` используется его каталог `opencode`.

Другие провайдеры, команды, выбранная модель и более строгие разрешения сохраняются. Существующий `opencode.jsonc` не изменяется и сохраняет приоритет над добавленными настройками. Перед изменением существующего файла установщик создаёт копию с суффиксом `.codexbridge-backup`.

Для полного набора дополнительных плагинов, MCP, LSP и субагентов можно отдельно подготовить локальные профили:

```sh
npm run setup:snip
npm run setup:playwright
npm run bundle:all
npm start -- quiet /absolute/path/to/project
```

В CLI: `/codex Исправь ошибку и проверь тесты`. Плагин вернёт `threadId`; передай его следующему вызову инструмента `codex`, чтобы продолжить ту же сессию. Модель берётся из настроек Codex; поле `model` позволяет явно выбрать другую. Мост использует свою зафиксированную зависимость `@openai/codex@0.159.3`, а не случайную глобальную версию.

`npm run connect:codex` подключает существующий вход ChatGPT в Codex и сохраняет каталог моделей. Для нового входа выполни `npm run connect:codex -- --login`: мост откроет официальный браузерный вход через Codex App Server. В уже настроенном OpenCode эти способы доступны через `/connect` → **Codex via bridge**. Учётные данные обрабатывает официальный Codex.

Обычные сообщения OpenCode также используют этот вход: в `/models` выбирай **Codex via bridge**. Сборка сохраняет модель из настроек Codex, если она есть в каталоге, иначе использует модель по умолчанию из каталога. Для коротких служебных запросов используется `gpt-5.6-luna`, когда она присутствует в каталоге. Смена модели сохраняет инструменты и диалоги разрешений OpenCode. После смены аккаунта обнови каталог командами `npm run connect:codex` и `npm run setup:opencode`, затем перезапусти CLI. Для локальных профилей также выполни `npm run bundle:all`.

Мост получает access token через локальный RPC `getAuthStatus` и поручает обновление самому Codex. В хранилище OpenCode записывается только несекретная отметка `codexbridge-managed`; токен используется в памяти для запросов Responses. Основной агент OpenCode отправляет эти запросы через адаптер моста, а инструмент `/codex` делегирует целый ход App Server по stdio. Каталог `model/list` может быть кешированным: доступ к выбранной модели подтверждается завершённым запросом, а не одним наличием в списке. [Протокол Codex App Server](https://learn.chatgpt.com/docs/app-server).

## Профили

| Профиль | Запуск | Поведение |
| --- | --- | --- |
| quiet | `npm start -- quiet /project` | Профиль по умолчанию: Codex, планирование, MCP документации, LSP и snip; уведомления отключены |
| jarvis | `npm start -- jarvis /project` | Тот же набор инструментов с уведомлениями Smart Voice Notify |

`npm run bundle` создаёт `quiet`; `npm run bundle:all` создаёт оба профиля. `npm start` запускает `quiet` в каталоге сборки.

Конфигурации профилей создаются в `.local/profiles/`. `bundle` изменяет только сгенерированный профиль; глобальное подключение обновляет `setup:opencode`. OpenCode объединяет профиль с личными настройками. Постоянные изменения профиля вноси в генератор либо в проектные настройки.

Jarvis сохранён в MCP-конфигурации как отключённая дополнительная интеграция. Smart Voice Notify обслуживает уведомления; его TTS и звуки отключены.

В профили добавлены собственные субагенты **`@designer`**, **`@devops`**, **`@tester`**. Они наследуют выбранную модель моста и правила разрешений. Зависимости зафиксированы lockfile. Install-скрипты npm отключены: Plannotator иначе изменяет глобальные команды. Генератор использует уникальные имена файлов для каждого плагина — OpenCode 1.3.2 объединяет одинаковые basename и молча теряет часть плагинов.

В обоих профилях включены OpenAI Docs, Context7 (`https://mcp.context7.com/mcp`), Grep (`https://mcp.grep.app`) и Playwright. Первые три — удалённые серверы; их доступность и ограничения определяются сервисами. Playwright запускается локально через `scripts/playwright-mcp.mjs` с `--isolated --headless`. `npm run setup:playwright` устанавливает Chromium в `.local/playwright/browsers/` этой сборки. Скриншоты и другие результаты сохраняются в `.local/mcp-artifacts/playwright/` **текущего проекта**. Профили личного браузера не используются. [MCP в OpenCode](https://opencode.ai/docs/mcp-servers/), [Playwright MCP](https://github.com/microsoft/playwright-mcp).

## Системный доступ

Codex стартует с `workspace-write`, `approvalPolicy: on-request`, `approvalsReviewer: user`. До делегирования OpenCode запрашивает разрешение `codex`. Выход за разрешённые границы передаётся в отдельный запрос `codex_system` с командой, директорией и причиной. Ответ применяется к конкретной операции; запрос расширения прав ограничен одним ходом. Модель не получает инструмент самостоятельной выдачи разрешений.

Отмена OpenCode прерывает ход и завершает дочерний процесс. Ошибка содержит известные `threadId`/`turnId`. После обрыва проверь изменения перед повторным запуском: отмена не откатывает уже выполненные действия. Продолжить сессию другого проекта нельзя; параллельное продолжение одного `threadId` отклоняется.

Произвольные интерактивные вопросы Codex пока не пересылаются как текстовые формы OpenCode; неподдерживаемые RPC получают явную ошибку. Мост не включает `danger-full-access` и не запускает `sudo` сам по себе.

## MCP для harness и других клиентов

```json
{
  "command": "node",
  "args": ["/absolute/path/to/CodexBridge/packages/bridge/dist/mcp.js"],
  "env": { "CODEXBRIDGE_PROJECT": "/absolute/path/to/target-project" }
}
```

Это транспортный пример: внешняя схема конфигурации зависит от клиента. MCP-вход содержит инструмент `codex`. Системный доступ подтверждается через MCP form elicitation; если клиент не поддерживает её, запрос отклоняется. Для OpenCode используй нативный плагин, чтобы разрешения отображались прямо в терминале. При длинных задачах увеличь timeout инструментов клиента. Существующий репозиторий harness здесь не изменяется.

## Проверки

```sh
npm run doctor -- --mcp
npm run check
npm run smoke:mcp
# Все MCP должны ответить; недоступный дополнительный сервер считается ошибкой:
npm run smoke:mcp -- --strict
# Только локальные MCP и тестовый сайт на localhost:
npm run smoke:mcp -- --offline
npm run smoke:lsp
npm run smoke:opencode
npm run smoke:startup # обычный OpenCode с глобальным подключением моста
npm run smoke:codex
# Отдельно: использует лимит настроенной модели Codex
npm run smoke:inference
npm run smoke:provider
```

Текущие результаты и границы проверки — в [docs/validation.md](docs/validation.md).
