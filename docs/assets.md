# Графический пак 0.2.0

Пользовательский референс: `assets/reference/team.png`. Исходная генерация ImageGen сохранена без изменений в `packages/companions/assets/source/team-generated-rgb.png`; тексты запросов — в `docs/imagegen-prompts.md`.

Шахматный фон удалён технической обработкой по поручению пользователя. Скрипт `scripts/prepare-sprites.py` выделяет нейтральный фон, сохраняет тёплые белые участки одежды, убирает отдельные точки и выравнивает шею и подошвы во всех кадрах. Он не рисует новые лица, одежду или скрытые под предметами части тела. Для повторной сборки нужны Python 3, Pillow и NumPy:

```sh
python3 scripts/prepare-sprites.py
```

## Контракт атласов

Все три базовых PNG имеют настоящую прозрачность RGBA и одинаковые размеры **1024 × 1536**: 4 столбца × 4 строки, ячейка **256 × 384**. Масштабировать с сохранением пропорций **2:3** и без интерполяции внутренних пикселей; нативный renderer отдельно смягчает прозрачный край, как описано ниже. Координаты идут от левого верхнего угла. Все имена атласов в этом документе относятся к `packages/companions/assets/`.

| Поле | Значение |
| --- | --- |
| Столбцы 0–3 | `lead`, `code`, `research`, `review` |
| Строки 0–3 | `idle`, `talking`, `blink`, `working` |
| Общая точка шеи | `(128, 120)` |
| Верх головы | около `y=24` |
| Линия подошв | `y=368` |
| Полный персонаж | `team-atlas.png` |
| Волосы, лицо, встроенные аксессуары головы | `head-atlas.png` |
| Одежда, руки, предметы в руках | `body-atlas.png` |
| Машиночитаемое описание и границы кадров | `atlas.json` |

Исходные `head-atlas.png` и `body-atlas.png` сохраняют разбиение референса: одинаковые столбец и строка этих двух слоёв побитово восстанавливают соответствующий кадр `team-atlas.png`. Поле `headSplitRatio` указывает высоту общей точки шеи, а не линию для обрезки слоёв. Для смешанной внешности renderer использует отдельную исправленную пару, описанную ниже.

Это **два слоя внешности**, которые дают 16 сочетаний головы и одежды. Очки, гарнитуры и наушники принадлежат голове; руки, книги и планшеты — одежде. Отдельных переключателей аксессуаров нет: для этого нужны дополнительные рисунки скрытых областей и отдельные маски. Жест руки исследовательницы остаётся жестом поправления очков и при выборе другой головы.

## Смешанная внешность без чужих воротников

`mixed-head-atlas.png` и `mixed-body-atlas.png` имеют ту же сетку **1024 × 1536**. Они применяются только при `headColumn != bodyColumn`: сначала тело, затем голова в том же прямоугольнике. Волосы и лицо сохраняются в голове, воротник и плечи остаются у выбранной одежды. Скрытые под волосами участки одежды и шеи дорисованы ImageGen. Маска ограничивает замену областью снятой головы; исходные пиксели одежды снаружи этой области и ниже `y=260` сохраняются, что проверяется скриптом.

Исходник ремонта, точный запрос и регистрация: `source/layered-bodies/generated.png`, `prompt.json`, `registration.json`. Последний содержит опорные точки, хеши входов и выходов, число пикселей ремонта. Команда требует Pillow и выполняется после подготовки базовых спрайтов:

```sh
python3 scripts/prepare-layered-bodies.py
```

В `source/layered-bodies/` сохраняются листы `before-<state>-<background>.png` и `after-<state>-<background>.png`: 16 сочетаний для каждого из четырёх состояний, на светлом и тёмном фоне. Цельные пресеты продолжают использовать исходный `team-atlas.png` и полные кадры анимации.

- `packages/companions/assets/preview-combinations.png` — все 16 сочетаний головы и одежды в состоянии ожидания.

Базовое состояние `talking` остаётся резервным вариантом при отсутствии лицевого атласа v3. В расширенном паке используются отдельные формы рта, описанные ниже; их выбор не распознаёт фонемы. Источник — иллюстрация с пиксельной стилизацией; техническая обработка не преобразует её в заново нарисованный низкоразрешённый pixel art.

Повторная регистрация выполняется двумя скриптами с Pillow и NumPy: первый обрабатывает CODE и RESEARCH, второй — LEAD и REVIEW. У CODE и RESEARCH исходники имеют нарисованный шахматный фон, у LEAD и REVIEW — однотонный пурпурный; техническая обработка превращает их в настоящую прозрачность:

```sh
python3 packages/companions/assets/source/animation-v3/code/prepare.py
python3 packages/companions/assets/source/animation-v3/lead/prepare.py
```

После подготовки **всех четырёх ролей** общий сборщик с Pillow упаковывает клипы и лицевой атлас, создаёт `animation-v3.json`, проверяет размеры, прозрачные поля, линию подошв и отсутствие одинаковых RGBA-кадров внутри роли с учётом v2:

```sh
python3 scripts/assemble-animations-v3.py
npm run companion:build
```

`animation-v3.json` содержит `cell`, `columns`, `feetBaseline`, `clips`, `facial`, `counts` и записи кадров с SHA-256 и исходным индексом. `CharacterMotion.swift` загружает манифесты v2 и v3 вместе. Успешная упаковка не заменяет визуальную проверку рисунков и нативного renderer; фактические результаты сборки записываются отдельно в `docs/validation.md`.

## Мимика v3

`facial-v3.png` имеет размер **1024 × 6912**: четыре столбца ролей, 18 строк, та же ячейка **256 × 384**. В исходной папке каждой роли `face-registered.png` содержит один столбец размером **256 × 6912**. Это прозрачные накладки внутри лица, зарегистрированные по исходному `team-atlas.png` в позе idle, а не новые головы или полноразмерные позы.

| Строки | Содержание |
| --- | --- |
| 0–7 | закрытый рот, слегка открытый, A, O, E, I, U, улыбка во время речи |
| 8–13 | глаза открыты, четверть, половина, три четверти закрытия, закрыты, повторное открытие |
| 14–17 | улыбка, беспокойство, сосредоточенность, удивление |

Для форм рта заменяется только околоротовая область, для моргания — глаза и брови, для эмоций — внутренняя часть лица. Силуэт волос и размещение аксессуаров сохраняются; край маски смягчён внутри лица. Новые пиксели берутся из генераций, а геометрия регистрации и маски записана в `registration.json`. `face-before-after.png` показывает исходное лицо рядом с результатом каждой накладки.

Во время речи renderer использует исходную спокойную позу и накладывает рот и моргание. Эти же накладки работают на голове смешанного персонажа. На движущиеся цельные позы они не накладываются: головы в этих кадрах меняют положение. Между клипами на спокойной позе показывается эмоция текущего состояния. Амплитуда WAV или события системного синтезатора управляют открытием рта; буквы в названиях кадров описывают рисунок, а не точную синхронизацию с фонемами.

## Нативное движение и отрисовка

Появление длится **600 мс**, смена роли или внешности — **700 мс**, уход — **450 мс**. Клип состояния проигрывается при его изменении и повторяется с переменными паузами; рисунки дополняются небольшим дыханием и эффектами перехода. Речь управляет ртом через амплитуду WAV либо события слов системного синтезатора, без фонемной артикуляции.

`SpeechBubbleView.swift` переносит полную текущую реплику по словам, позволяет выделение и копирование. Высота облачка ограничена 168 точками; при превышении появляется вертикальная прокрутка. `SpeechRouter` воспроизводит один голос и одновременно готовит не более одной следующей реплики локальным TTS. Длинные ответы делятся на короткие фрагменты, а облачко обновляется для звучащего фрагмента.

`SpriteCache.swift` кеширует кадры и сглаживает только границу прозрачности примерно на **один физический экранный пиксель** с учётом масштаба и Retina. Непрозрачная внутренняя часть остаётся резкой. Это обработка края при отображении; исходные атласы не размываются.

При системном уменьшении движения декоративные перемещения, частицы и рисованные клипы отключаются; переход использует изменение прозрачности за **150 мс**. Таймер отрисовки работает с частотой 24 кадра в секунду только для видимой непустой группы. Обычный запуск, включая старую настройку `showOnStart: true`, не создаёт персонажей и не запускает этот таймер. Демонстрация включается явно и не заменяет сохранённые реальные сессии.

Нативная проверка использует отдельную копию приложения, без синтеза речи и записи микрофона:

```sh
node scripts/smoke-companions.mjs
node scripts/smoke-companions.mjs --visual --scale=0.5
node scripts/smoke-companions.mjs --visual --scale=1
node scripts/smoke-companions.mjs --visual --scale=2
```

Проверяются пустой запуск, реальные персонажи, скрытие без автоматического показа по событиям, возврат из демонстрации и завершение ухода. Визуальный режим сохраняет состояния, переходы и смешанную внешность на светлом и тёмном фоне в `.local/companions-snapshots/scale-<scale>/`. Это снимки нашего renderer через его IPC, а не скриншоты других приложений. Конкретные результаты запусков и оставшиеся ограничения перечислены в `docs/validation.md`.
