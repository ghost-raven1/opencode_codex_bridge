## Добавлено в генератор сборки

[agent-config.mjs](../scripts/lib/agent-config.mjs) определяет три собственные роли. Их тексты написаны для этой сборки, без копирования сторонних prompts.

| Роль | Когда поручать задачу | Что получить |
| --- | --- | --- |
| `designer` | Изменение интерфейса, визуальная иерархия, адаптация размеров и доступность | Изменения в существующем UI-стеке и результат визуальной проверки, если она доступна |
| `devops` | Ошибки запуска, сборки, CI и конфигурации окружения | Минимальное исправление с командами воспроизведения и проверки |
| `tester` | Поиск багов, регрессии и пользовательские сценарии | Воспроизведение, тест и проверенное исправление, когда исправление входит в поручение |

Роли подключены через `agent` во всех трёх профилях генератора. В CLI их можно вызвать через `@designer`, `@devops`, `@tester` или поручить основной модели делегирование соответствующему специалисту. Обычный `build` остаётся основным агентом.

У ролей `mode: "subagent"`, без отдельных `model`, `variant`, `tools` и `permission`. При вызове через `task` модель берётся у родительского агента — в стандартном профиле это выбранная модель `codexbridge/*`. Основание: [task.ts версии 1.3.2](https://github.com/anomalyco/opencode/blob/v1.3.2/packages/opencode/src/tool/task.ts). Правила доступа наследуются из профиля и проекта; роли не заменяют `codex`/`codex_system: "ask"` собственным разрешением. Механизм объединения описан в [agent.ts версии 1.3.2](https://github.com/anomalyco/opencode/blob/v1.3.2/packages/opencode/src/agent/agent.ts).

## Проверка и применение

Контрактный тест `tests/agent-config.test.ts` проверяет наличие трёх субагентов и отсутствие переопределения модели и разрешений. `scripts/smoke-opencode.mjs` дополнен проверкой реального `/agent`: роли доступны, модель не закреплена отдельно, правила моста остаются `ask`.

Все три локальных профиля перегенерированы. Проверка настоящего OpenCode 1.3.2 через `/agent` прошла: три роли доступны, модель наследуется, `codex` и `codex_system` сохраняют `ask`. Чтобы повторно применить изменения:

```sh
npm run bundle:all
npm run smoke:opencode
```

Успех контрактного теста не заменяет запуск роли моделью: обнаружение через `/agent` и фактическое выполнение делегированной задачи — отдельные уровни проверки.
