# Проверка 0.2.0 — 2026-10-02

Ветка `feature/opencode-codex-bridge`, macOS 27 arm64, M1 Pro / 16 ГБ, Node 24.15.0, OpenCode **1.3.2**. Проверено локально. Git remote отсутствует; публикации и запуска GitHub CI не было.

`npm run check`: **205/205 Vitest**, strict TypeScript и сборка обоих workspace — PASS. Нативная сборка, `test:native` и smoke выполнены отдельно.

## Исправление преждевременного ухода и темпа анимаций

- Воспроизведены три случая преждевременного удаления: `idle` до первого ответа, во время незаконченного ответа и при работающих инструментах. Теперь завершение требует окончания сообщения ассистента и всех инструментов; промежуточные шаги `tool-calls`/`unknown` не считаются завершением задачи. Семь новых регрессий проверяют также пропущенное начальное событие, возобновление генерации, поздний результат инструмента и очередь речи. Интервал ухода сохранён: **10 секунд после завершения и озвучки**.
- `node scripts/smoke-companion-activity.mjs` запускает настоящий OpenCode с изолированным локальным провайдером. Долгий инструмент и подставленное запоздалое `idle` больше не удаляют персонажа; после финального ответа он уходит через 10 секунд. Это проверка реального потока событий без обращения к аккаунту модели; отчёт — `.local/companions-activity-smoke.json`.
- Клипы состояний замедлены до **3.2–4.5 секунды**, удержание позы — **400–600 мс**. Появление занимает **1.2 секунды**, смена роли — **1.4 секунды**. Мимика речи обновляется до четырёх форм в секунду. Скорость моргания и уход за 450 мс сохранены. Обновлены манифесты, воспроизводящие скрипты и GIF; PNG и количество уникальных рисунков не менялись.
- Swift-проверки подтверждают минимальную длительность кадра, совпадение переходов с манифестами и достижимость всех 60 кадров. Повторная нативная сборка, `test:native`, visual smoke масштаба 1 с 23 PNG и отдельный smoke уменьшения движения прошли.

## Исправления и воспроизводящие проверки

- Диктовка сохраняется перед отправкой события в OpenCode: последние 20 текстов каждого канонического проекта, атомарная замена, `0600`, каталог вне Git. Проверены потеря соединения, успешный HTTP без подтверждения вставки, восстановление после перезапуска, явная повторная вставка, копирование, очистка и отсутствие автоматической отправки запроса. Две открытые истории одного проекта больше не перетирают друг друга; зависшая HTTP-доставка не блокирует сохранение следующей записи.
- Файловая блокировка проверена на гонках освобождения и восстановления после аварии. Шесть настоящих Node-процессов сохранили все 30 конкурентных изменений; после SIGKILL владельца восстановление заняло 24 мс. Новый владелец защищён уникальным owner-token.
- Отсутствующий результат `tool.execute.after` не вызывает вторичную ошибку плагина. Поздно обнаруженная завершённая подзадача получает terminal-состояние вместо бесконечного working.
- Служебные summaries и synthetic continuation не озвучиваются; исходное задание, роль и task ID сохраняются. Поздние события прежней задачи не меняют нового персонажа и не возвращают исчезнувшего.
- Публичные сообщения делегированного Codex проходят только через `metadata.codexSpeech`. Проверены run/thread/message IDs, завершение, дедупликация, отмена и отдельный персонаж. Реальный OpenCode **1.3.2** с локальным stub-провайдером и stdio fixture сохранил финальную metadata после `tool.execute.after`: ровно два публичных сообщения, без reasoning и произвольного вывода инструментов. Это проверка runtime-контракта без обращения к модели.
- Русские намерения, включая «поищи баги», отрицания и смешанные задания, покрыты тестами. Metadata сессии сама по себе больше не создаёт персонажа.
- Проверены отмена синтеза/проигрывания, поздние callbacks, освобождение worker, переподключение через явный `companion → show`, несколько проектов, повтор после HTTP 401 и гонка обновления токена. Принудительное обновление токена проверено fixtures, действующая авторизация пользователя не сбрасывалась.

Context7 выполнил resolve-library-id и query-docs; Grep вернул фрагменты публичного репозитория; Playwright выполнил navigate → snapshot → click → snapshot → screenshot. ## Нативное приложение, графика и звук

- Swift собирается без предупреждений; приложение ad-hoc подписано. Root package, оба workspace и нативное приложение синхронизированы на **0.2.0**.
- Native smoke проверяет ноль персонажей со старым `showOnStart:true`, появление первого агента, скрытие без перерисовки, сохранение скрытия при событиях задач, показ реальных персонажей, отдельное демо и восстановление сессии, исчезновение последнего персонажа и остановку таймера. Проверены повторная смена роли до завершения перехода, отмена ухода новой активностью и режим уменьшения движения. QA использует отдельный bundle ID и удаляет свои процессы/настройки.
- Lifecycle-тесты проверяют ожидание разрешения и очереди речи, 10 секунд после завершения и опустошения очереди, отмену ухода новой активностью, защиту говорящего при переполнении, четыре разных тембра и смену роли без занятия чужого голоса.
- По расширенному запросу ImageGen подготовлены **240 кадров тела и 72 лицевых**: ровно 60+18 на каждую героиню. V2 содержит 80 body, V3 добавляет 160 body и 72 face overlays. Сборщик и Vitest проверяют реальные RGBA-хеши без повторов, прозрачные границы, положение стоп и контракт клипов. Нативный тест подтвердил достижимость всех 60 кадров каждой роли через временную шкалу. Источники, точные запросы, технические скрипты и GIF сохранены в `source/animation-v2/` и `source/animation-v3/`.
- Нативные smoke-проверки прошли в масштабах 0.5/1/2 на Retina и отдельно с уменьшением движения: по 23 PNG в каждом прогоне. Кадры просмотрены на светлом и тёмном фоне, включая длинную реплику одного персонажа и смешанную внешность. Вырезы воротников и потерянный рукав CODE восстановлены фрагментами ImageGen в отдельных mixed-атласах. Просмотрены 64 комбинации головы/одежды по четырём состояниям; тест защищает восстановленный рукав: 899 из 900 пикселей в проблемной области вместо 80.
- Старые спрайты очищены от закрытых островков фона и светлого матте по контуру волос. Лица, светлая одежда, серебряные волосы и обувь защищены масками. Четыре Python-регрессии проверяют удаление фона, сохранение деталей и очистку кромки. В V2 удалено 1179 пикселей фона и восстановлено 1585 исходных пикселей лица CODE; геометрия сохранена.
- Облачко переносит весь текст и прокручивается при превышении 168 точек. Нативные проверки прошли 15 раскладок, включая Unicode, длинные слова без пробелов, смену ширины и достижимость последней строки. Исправлены и проверены возможность панели получать фокус для копирования, запуск нового клипа после отмены ухода и снимок состояния без анимации появления.
- Найден реальный дефект: `AVAudioPlayer(contentsOf:)` блокировал main thread при чтении WAV из Documents. Та же WAV из временного каталога воспроизводилась за ~0.9 с. Рабочие WAV перенесены в отдельные каталоги `~/Library/Caches/CodexBridge/audio/` с правами `0700`; каждый worker владеет только своим каталогом. Модель и её зависимости остаются локальными в проекте.
- После исправления настоящий цикл TS → Qwen3-TTS / MLX → WAV → AVAudioPlayer завершился **4/4 audio-finished:end**. Serena: 8.63 с генерация / 2.80 с аудио; Vivian: 2.50 / 3.60; Sohee: 2.84 / 4.16; Ono_Anna: 2.78 / 3.84. После завершения каталог WAV пуст. Предыдущие неуспешные прогоны до исправления не считаются прохождением.
- Устранено ожидание синтеза между репликами: один worker готовит одну следующую фразу во время воспроизведения. Тесты сохраняют порядок, четыре голоса и отмену готового/незавершённого prefetch при stop, mute, диктовке и dispose; сбой подготовки не обрывает текущую реплику. Настоящий `benchmark-speech.mjs --mode=both` завершил 8/8 проигрываний. Паузы по callbacks AVAudioPlayer: до исправления 10.0458/9.9752/10.2311 с (средняя 10.084), после 0.0471/0.4402/0.0470 с (средняя 0.1781). Это события плеера, не акустический замер; Qwen генерирует стохастически. Первая генерация и поздно поступившая фраза всё ещё могут требовать ожидания.
- Четыре публичных образца существующих тембров Qwen с production-профилями сохранены в `.local/tts/voice-previews/`; общий `preview.wav` длится 20.1 с. Это синтетические примеры, не запись микрофона и не обучение новых голосов. Воспроизведение: `node scripts/generate-voice-previews.mjs`.
- Снимки QA тоже сначала создаются во временном каталоге: нативному приложению не нужен доступ к Documents ради PNG. Host переносит результат в каталог артефактов проекта.
- Акустическая проверка остаётся **незавершённой**. Ранний запуск распознал контрольную фразу (`phraseMatched:true`). После повторной ad-hoc подписи и выдачи разрешений три повтора запускали запись и возвращали непустой текст, но не распознали слова контрольной фразы (`phraseMatched:false`). Пользователь подтвердил звук из динамиков и попросил переключиться на графику. Microphone и Speech были authorized, on-device ru-RU доступен; аудио и полный распознанный текст не сохранялись. Это не позволяет объявить окончательную акустическую проверку пройденной.
