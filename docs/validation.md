## Скелет, ноги и прерывание жестов — 2026-10-04

- Добавлен полный 2D-скелет для семи героинь и **91 рига**: семь стоячих, 42 рабочих ракурса, 28 танцевальных и 14 шагающих. Каждый содержит **17 костей**, риги с отдельным предметом — 18. Таз → позвоночник → грудь → шея → голова; плечо → предплечье → кисть; бедро → голень → стопа. Цельные участки тела/рук/ног используют линейный skinning существующих текстур; предмет следует кисти. Вершины/веса подготавливаются при загрузке позы, новые PNG не создавались. Экспорт проверил неизменность 457 исходных слоёв.
- Двухсуставная IK удерживает стопы при переносе веса и сохраняет длины бедра/голени. Во время ходьбы опорная стопа остаётся на месте, переносимая поднимается; движение под музыку применяется к тазу и суставам, используя переданный ритм. Максимальная ошибка опорного сустава в проверке 91 рига — `2.41e-13` исходного пикселя. Смешанные головы используют кости одежды и своё совмещение шеи. Reduce Motion возвращает точную bind-позу.

Треугольники теперь заменяют общие пиксели во временном слое, который композится один раз. Нативные проверки прошли 15 раскладок, включая Unicode, длинные слова без пробелов, смену ширины и достижимость последней строки. Исправлены и проверены возможность панели получать фокус для копирования, возобновление персонажа после отмены ухода и снимок состояния без анимации появления.
- Найден реальный дефект: `AVAudioPlayer(contentsOf:)` блокировал main thread при чтении WAV из Documents. Та же WAV из временного каталога воспроизводилась за ~0.9 с. Рабочие WAV перенесены в отдельные каталоги `~/Library/Caches/CodexBridge/audio/` с правами `0700`; каждый worker владеет только своим каталогом. Модель и её зависимости остаются локальными в проекте.
- После исправления настоящий цикл TS → Qwen3-TTS / MLX → WAV → AVAudioPlayer завершился **4/4 audio-finished:end**. Serena: 8.63 с генерация / 2.80 с аудио; Vivian: 2.50 / 3.60; Sohee: 2.84 / 4.16; Ono_Anna: 2.78 / 3.84. После завершения каталог WAV пуст. Предыдущие неуспешные прогоны до исправления не считаются прохождением.
- Устранено ожидание синтеза между репликами: один worker готовит одну следующую фразу во время воспроизведения. Тесты сохраняют порядок, четыре голоса и отмену готового/незавершённого prefetch при stop, mute, диктовке и dispose; сбой подготовки не обрывает текущую реплику. Настоящий `benchmark-speech.mjs --mode=both` завершил 8/8 проигрываний. Паузы по callbacks AVAudioPlayer: до исправления 10.0458/9.9752/10.2311 с (средняя 10.084), после 0.0471/0.4402/0.0470 с (средняя 0.1781). Это события плеера, не акустический замер; Qwen генерирует стохастически. Первая генерация и поздно поступившая фраза всё ещё могут требовать ожидания.
- Четыре публичных образца существующих тембров Qwen с production-профилями сохранены в `.local/tts/voice-previews/`; общий `preview.wav` длится 20.1 с. Это синтетические примеры, не запись микрофона и не обучение новых голосов. Воспроизведение: `node scripts/generate-voice-previews.mjs`.
- Снимки QA тоже сначала создаются во временном каталоге: нативному приложению не нужен доступ к Documents ради PNG. Host переносит результат в каталог артефактов проекта.
- Акустическая проверка остаётся **незавершённой**. Ранний запуск распознал контрольную фразу (`phraseMatched:true`). После повторной ad-hoc подписи и выдачи разрешений три повтора запускали запись и возвращали непустой текст, но не распознали слова контрольной фразы (`phraseMatched:false`). Пользователь подтвердил звук из динамиков и попросил переключиться на графику. Microphone и Speech были authorized, on-device ru-RU доступен; аудио и полный распознанный текст не сохранялись. Это не позволяет объявить окончательную акустическую проверку пройденной.

## Границы проверки

Настоящий браузерный вход с ручным выбором нового аккаунта не повторялся: используется действующая авторизация. Наличие восьми моделей в каталоге не доказывает вызов каждой модели. Ручное подтверждение OS-команды в пользовательском TUI не повторялось, транспорт разрешений проверен fixtures. Субъективное качество голосов и фонемная точность не заявляются: mouth animation использует амплитуду WAV или word callbacks macOS. Windows/Linux, другой Mac и CI не проверены.
